\paragraph{Description} AgentRx redefines the target as the \emph{critical failure step}---the first failure by any agent from which the run never recovers---and adds a \textbf{root-cause category}. The dataset is the evaluation set of the AgentRx debugging framework (constraint synthesis $\to$ step-wise checking $\to$ LLM judge). All failures are natural, from four domains:
\begin{itemize}
\item \textbf{$\tau$-bench retail} (39, 29 public): single tool-calling agent (gpt-4o) + simulated user under a domain policy; median 36 steps.
\item \textbf{Magentic-One} (44, all public): failed runs \emph{sampled from Who\&When's Hand-Crafted subset}; median 31.5 steps (paper reports 33).
\item \textbf{Flash} (42) and \textbf{RelWork} (45; five trajectories from each of nine MAST / Who\&When settings): not public.
\end{itemize}
\textbf{Annotation}: grounded-theory open coding by three annotators in two phases---(1) exhaustive marking of \emph{every} step where an agent fails to make progress, including later-recovered ones; (2) identification of the critical failure and its category. Codes were merged until saturation, then frozen. On 30 trajectories labelled by all three, pairwise Cohen's $\kappa$ = 0.87--0.93 (\textbf{mean 0.89}); 20--24 min per trajectory. \textbf{Taxonomy} (9 categories in ground truth; the repo/judge adds a 10th, Inconclusive; one per critical step, disambiguated by a yes/no checklist): Instruction/Plan Adherence, Invention of New Information, Invalid Invocation, Misinterpretation of Tool Output, Intent--Plan Misalignment, Under-specified User Intent, Intent Not Supported, Guardrails Triggered, System Failure. Labels: per-failure \code{step\_number}, \code{failed\_agent}, \code{failure\_category} and reasons; one \code{root\_cause} per trajectory.

\paragraph{Metrics and baselines} Exact step accuracy, Acc@$\pm$1/3/5, average step distance; category accuracy against the critical failure (also against any / earliest / terminal failure); failed-agent accuracy. gpt-5 judge, mean of 3 runs, in \% (paper). W\&W$^*$ = the Who\&When all-at-once prompt adapted to the first-unrecoverable definition.

\paragraph{Schema} GitHub \code{data/}: \code{ground\_truth/tau\_ground\_truth.json} (29) and \code{magentic\_one\_ground\_truth.json} (44), each a list of \{\code{trajectory\_id}, \code{failure\_summary}, \code{failures}: [\{\code{failure\_id}, \code{step\_number}, \code{step\_reason}, \code{failure\_category}, \code{category\_reason}, \code{failed\_agent}\}], \code{root\_cause}: \{\code{failure\_id}, \code{reason\_for\_root\_cause}\}\}. Trajectories: \code{tau\_retail/tau\_dataset\_failed.json} (OpenAI chat messages with \code{tool\_calls}; \code{step\_number} is 1-based and counts the system message) and \code{magentic\_dataset/<id>.json} (lists of \{\code{content}, \code{role}\} with roles such as \code{Orchestrator (thought)}, \code{Orchestrator (-> WebSurfer)}, \code{WebSurfer}). Additional repo files include \code{tau\_retail/tau\_dataset\_full.json} (100 runs: 73 succeeded, 27 failed, omitting tasks 104--105), a 24-row subset \code{ground\_truth/tau\_retail.json}, 14 extra unannotated logs in \code{magentic\_dataset/} (58 total), and 18 sample logs in \code{trajectories/}. Domain policies (\code{retail\_policy.txt}; \code{magentic\_policy.txt}, which is malformed JSON) and 26 example $\tau$-retail tool-call/response messages (\code{tool\_schemas/tools\_structure.json}, covering 13 tools rather than formal JSON Schemas) are included. Per the HF card, the gated \code{default} files (\code{tau\_retail.jsonl}, \code{magentic\_one.jsonl}) add \code{root\_cause\_failure\_id}, \code{root\_cause\_reason}, and \code{num\_failures}, alongside a \code{trajectories} config (\code{magentic\_dataset.jsonl}, \code{tau\_retail\_dataset.jsonl}).

\paragraph{Notes} (i) Only partially public: HF is gated and the released GitHub subset covers 73 of 170 trajectories; the proprietary Flash traces, where AgentRx scores highest, cannot be inspected. (ii) The root cause is not the first failure in 26\% of public trajectories (39\% of Magentic-One), because orchestrators recover from early mistakes; the paper's example 5f982798 is labelled step 3 by Who\&When and step 33 by AgentRx. (iii) All 44 Magentic-One logs come from Who\&When Hand-Crafted, so results on the two benchmarks are not independent; \code{magentic\_dataset\_whowhen/} holds the 16-of-44 subset where Who\&When and AgentRx agree on root-cause step (in the same AgentRx JSON list format, byte-identical to \code{magentic\_dataset/}). (iv) Every failure event is annotated (up to 55 per trajectory), enabling earliest/any/terminal-failure metrics. (v) Label hygiene: category strings vary in casing/phrasing (\code{Instruction Adherence Failure} vs \code{Instruction/Plan Adherence Failure}, \code{Intent not supported} vs \code{Intent Not Supported}, unhyphenated \code{Intent Plan Misalignment}, \code{Invention of new information}, \code{Underspecified User Intent}, \code{Websurfer} vs \code{WebSurfer}); one \code{failure\_id} is a string (\code{"1"} in \code{08cae58d}); one Magentic-One record (\code{72e110e7}) has empty \code{step\_reason}/\code{category\_reason} on two failures; \code{failed\_agent} may be the simulated \code{User}. (vi) Few agents per trajectory, so the informative targets are step and category; the same pipeline was also run on all 1,022 MAST trajectories without gold labels.
